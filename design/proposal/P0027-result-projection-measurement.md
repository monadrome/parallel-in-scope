# 冻结结果投影与查询测量

## 蒸馏摘要

- 核心出发点：冻结结果的重复统计、值投影和查询可能重复扫描或分配，须先测量。
- 不变量与拟议 MUST：MUST 保留输入顺序失败优先级、取消异常、成功 null、原 cause 与
  只读中断规则；优化 MUST 用当前版本测量证明收益。
- 被否决方向及理由：不引用旧版本 B/op 作为现行证据，不无条件增加缓存或名称索引；
  小组的线性查找不构成已证明的性能回归。

## 目标与论证

[TaskBatchResult](../../src/main/java/io/github/monadrome/parallelinscope/TaskBatchResult.java)
用 `orThrow()` 作为聚合失败闸门，完整统计只在 `outcomeCounts()` 被请求时构造。
失败检查与值收集的取舍见 [同步出口契约](../synchronous-scope-exit.md)。

改前改后用户代码均为 `batch.valuesOrThrow()`。报告缓存只有出现真实重复查询需求时再评估。
不改输入顺序失败优先级、纯取消异常、成功 null 和只读中断规则。不需要新公开类型。
本提案的统计缓存、共享索引和重复值投影仍是测量候选，不引用旧版本 B/op 数字证明收益。
承接 P0007 中未实施的测量方向；已落地的失败检查扫描优化不在本提案范围。

GroupValues/TaskGroupResult 按名称读遍 N 项可能重复定位；只在真实大组需求下评估共享索引。
用户代码改前改后均为 batch.valuesOrThrow() 或现有名称查询；无签名或迁移变化。

核心 followup 的成员值重复 fold（combine 输入与成功 GroupValues）、Group outcomeCounts
重复计数与运行中频繁图查询的派生投影成本同样只作为测量候选；正常关闭一次分析不等于
频繁查询瓶颈。当前图模型已更新，必须重新测量；复用值结构不得公开部分失败值或延长大对象寿命。

同步批次用于等待的完整观测聚合已从生产冻结路径移除：轻量发布屏障不收集值，内部完整列表
按需构造；输入快照与发布不变量见 [同步出口契约](../synchronous-scope-exit.md)。本提案仍只覆盖
未落地的结果投影、统计与查询测量，不把这次改动当作统计缓存或索引的证据。
