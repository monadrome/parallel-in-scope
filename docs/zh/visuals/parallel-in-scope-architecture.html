v0.3 执行架构

此页面已随 v0.3 重构：旧图中的 ParConfig、ParOptions 和运行期执行器解析不再存在，ParName 已更名为 ParId；任务组的两阶段「定义结构 + 绑定 body」也已改为一次性链式声明。

应用装配：ParRuntime 以 String 名注册多个 Par，并在构建期将每个入口绑定到 supplied executor。

一次性声明：ParRuntime.group* 返回 step builder 链（GroupStart → GroupStep → CombinedGroupStep）；每个 par 同时声明成员类型与本次 body，submitAll() 是唯一的准入与提交边界。草稿单线程、不可重放，提交后旧阶段全部失效。

单次调用：批次用 BatchOptions、成员用 TaskOptions 解析为 MultiTaskContext；任务组在一次 whileOpen 准入内完成全部准备与注册，再按声明顺序提交各 executor。

执行与观测：滑动窗口提交在取消或拒绝后为未提交任务写入终态；组完成经 completionFuture() 与调用方选择的 executor 回调观测。

维护：队列清理由执行器所有者负责，库不自动 purge；原 purger 保存在 dev/experimental 分支。

完整说明请阅读 使用指南、v0.3 迁移指南、v0.2 迁移指南 和 ADR 0005。
