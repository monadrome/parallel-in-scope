执行架构（0.4 开发线）

旧图中的 ParConfig、ParOptions 和运行期执行器解析不再存在，ParName 已更名为 ParId；任务组为一次性链式声明，0.4 起成员以 TaskKey<T> 类型化 key 声明与读取，不再使用 Class/TypeToken。

应用装配：ParRuntime.builder() 以 ParId 注册物理执行器，可选绑定 defaultPar；构建后拓扑不可变，注册的执行器由调用方拥有并负责关闭。

一次性声明：ParRuntime.group(name, timeout) 返回 step builder 链（GroupStart → GroupStep → CombinedGroupStep）；每个成员以 TaskKey<T>、Par 与本次 body 一并声明，runAll() 是唯一的执行边界。草稿单线程、不可重放，旧阶段全部失效。

单次调用：批次用 BatchOptions、成员用 TaskOptions 解析为 MultiTaskContext；每个元素在准备期即持有完整执行 future，滑动窗口只决定这些 prepared future 何时进入线程池。

执行与观测：map/runAll 同步等待并返回冻结的 ImmediateResult 数据；观测读 completions()/members()/terminal()。每个 ParRuntime 常开记录执行器间的同步等待（被等待单元运行在饥饿型池上时才记边），记录的等待首次成环时按成环分量打 JUL WARNING，executorWaitReport() 随时可读。

维护：队列清理由执行器所有者负责，库不自动 purge；原 purger 保存在 dev/experimental 分支。

完整说明请阅读 使用指南、协作式取消、v0.4 迁移指南、v0.3 迁移指南、v0.2 迁移指南 和 ADR 0005。
