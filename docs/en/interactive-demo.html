01

批量执行 · Par.map

滑动窗口提交：12 个账户查询共享同一批次身份，任意时刻最多 4 个活跃，完成一个补进一个。每个元素从创建起就有独立的 Task 视图，取消能直达正在运行它的线程。

BatchOptions.java
BatchOptions options = BatchOptions
        .timeout("fetch-account", Duration.ofSeconds(5))
        .parallelism(16);   // 滑动窗口：同时最多 16 个活跃

TaskBatchResult<Account> batch =
        httpPar.map(accountIds, client::fetchAccount, options);
02

Fail-fast 取消级联

任一元素失败，整批立即进入 fail-fast：运行中的兄弟任务收到中断（FAIL_FAST），从未进入窗口的按 GROUP_CANCELLED 丢弃。每次取消都携带归因，不再是一声不吭的 cancel(true)。

Par.map · parallelism = 4 · 8 tasks
T3 将在第 2 秒失败
⚠ fail-fast 已触发：T3 失败 → 运行中的 T4 / T5 / T6 按 FAIL_FAST 中断，排队中的 T7 / T8 按 GROUP_CANCELLED 丢弃；归因随 LeanCancellationException 一路带回调用方。
TIMEOUT自身或父级截止到期 FAIL_FAST兄弟任务失败牵连 GROUP_CANCELLED批次取消时仍在排队 MEMBER_CANCELLED成员被单独取消
待运行 · T3 将在 2s 时失败
FailFast.java
BatchOptions options = BatchOptions
        .timeout("fetch-orders", Duration.ofSeconds(2))
        .parallelism(4);

// 任一元素失败 → 整批 fail-fast：
// 运行中的兄弟任务按 FAIL_FAST 中断，
// 排队中的按 GROUP_CANCELLED 丢弃
TaskBatchResult<Order> batch =
        httpPar.map(userIds, client::fetchOrders, options);
03

Deadline 继承

子任务声明的 8s 超时只是请求值，真正生效的截止是 min(自身声明, 父级剩余)。父 scope 的 5s 像天花板一样压住整条调用链，无需手工传递剩余时间。

deadline = min(子声明 8s, 父剩余 5s)
待运行
QUEUED sync-orders[0] · 声明 8s
父 scope 截止 5s
子任务声明 8s
实际生效 min(8s, 5s) = 5s
0s 2s 4s 6s 8s
父级剩余 5.0s 子级声明剩余 8.0s 父级 5s 先生效 → 按 TIMEOUT 取消
DeadlineInheritance.java
// 父批次：整批 5s 截止
BatchOptions parent = BatchOptions
        .timeout("sync-user", Duration.ofSeconds(5));

httpPar.map(userIds, user -> {
    // 子批次声明 8s，实际生效 min(8s, 父级剩余)
    // —— 父级 deadline 是天花板
    BatchOptions child = BatchOptions
            .timeout("sync-orders", Duration.ofSeconds(8));
    return databasePar.map(user.orderIds(), db::syncOrder, child);
}, parent);
04

嵌套批次的任务图与死锁检测

map 里再开 map 会在任务图上留下等待边。观察 scope 持续收集这些边并检查环 —— http 等 database、database 又等回 http，就是潜在的池耗尽死锁。

TaskGraphObservationScope · 任务依赖图
待运行
⚠ 潜在死锁风险信号：http 批次的 worker 正在等待 database 批次，而 database 又反向等待 http —— 两个池的 worker 互相占满时整批将永久挂起。TaskGraphObservationScope 在运行时持续检查此类环。
DeadlockDetection.java
ParRuntime runtime = ParRuntime.global();
Par http = runtime.par(ParId.of("http"));
Par database = runtime.par(ParId.of("database"));

try (TaskGraphObservationScope graphs =
        runtime.openTaskGraphObservation()) {
    http.map(requests, req -> {
        User user = client.fetchUser(req.userId());
        // 嵌套批次：图上产生 http → database 的等待边
        return database.map(user.orderIds(), db::fetchOrder, options);
    }, options);

    if (TaskGraphObservationScope.hasTaskCycle()) {
        LOGGER.warning("检测到任务环 —— 潜在死锁风险信号");
    }
}
