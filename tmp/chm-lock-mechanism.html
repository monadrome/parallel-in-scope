ConcurrentHashMap 的锁：边界画在哪里

能用 CAS，就不加锁；必须加锁时，只锁一个 bin；读路径尽量不加锁 —— 基于 JDK 8（Corretto 8.412）源码
很多文章会直接回答“ConcurrentHashMap（CHM）用了什么锁”。更准确的问题是：一次操作到底触碰了多大的共享结构，哪些变化必须互斥，哪些变化可以靠 CAS 和 volatile 完成？

JDK 8 的答案集中体现在 putVal：空 bin 用 CAS，遇到扩容就协作迁移，只有修改已有 bin 的结构时才锁住 bin 头节点。

1. 锁的粒度，跟着数据结构走

实现主要锁范围结果
Hashtable整张表不同键的操作也互相阻塞
JDK 7 ConcurrentHashMap一个 segment并发度受 segment 数量限制
JDK 8 ConcurrentHashMap一个 bin 的头节点不同 bin 可以并行，空 bin 无需加锁

JDK 8 不再把表切成固定数量的 segment，而是把锁下沉到发生结构变化的 bin。这里的“一个 bin”通常是一条链表，冲突严重时也可能是 TreeBin。因此，锁的粒度不是固定的“一个桶”，而是当前 bin 的结构一致性范围。

两个线程操作不同 bin 时通常不争用同一把锁；只有哈希冲突落到同一 bin，或者操作触及同一结构时，才会产生竞争。

2. 三种同步手段，各自负责什么

机制解决的问题典型位置
volatile让线程看到已发布的状态表槽位、Node.val、Node.next
CAS原子地翻转一个槽位或计数状态空 bin 插入、sizeCtl、transferIndex、计数
synchronized保护一段结构性修改链表插入/删除、树操作、bin 迁移
一个字段

关注可见性，通常由 volatile 解决。

一个槽位

关注一次状态翻转，通常由 CAS 解决。

一条链或一棵树

关注结构完整性，需要互斥修改。

核心判断：锁的边界不是由“有没有并发”决定的，而是由“这次写入会不会破坏共享结构”决定的。

3. putVal：锁只出现在一个分支

图 2 · putVal 的决策树
put(key, value)
│
tabAt(tab, i) == null ?
├─ 是 → CAS 把新节点放入空 bin 不加锁
└─ 否 → f.hash == MOVED ?
├─ 是 → helpTransfer，迁移后重试 协作扩容
└─ 否 → synchronized (f)，修改已有 bin 加 bin 锁
进入 synchronized (f) 后还要再次检查 tabAt(tab, i) == f。线程等待锁期间，如果旧 bin 已迁移并替换成 ForwardingNode，双检失败，当前线程必须重新读取并重试。

4. 状态机：一个 bin 如何从空槽走到新表

图 3 · bin 状态转换图（实线 = 写路径，虚线 = 读路径）
CASbin 锁 / 结构修改无锁读路径
状态机的关键不变量：旧表槽位在迁移完成前仍指向完整旧 bin；迁移完成后才发布 ForwardingNode。因此写线程要么修改旧结构，要么转到新表，不会修改一条“拆到一半”的链。

5. 扩容：迁移者和写者使用同一把 bin 锁

JDK 8 扩容时不会原地重排旧链表，而是把一个旧 bin 拆到新表的两个位置：i 和 i + n。对同一个 bin，迁移和普通写入都以旧 bin 头节点 f 为锁对象，并使用同一个双检：

  1. 确认旧表槽位仍然指向 f；
  2. 在锁内构造并发布新表中的两个 bin；
  3. 最后把旧表槽位发布为 ForwardingNode。

线程撞到 ForwardingNode 后会调用 helpTransfer，通过 CAS 从 transferIndex 领取一段工作。锁只负责同一个 bin 的互斥，不同 bin 的迁移仍可以并行。

6. 读路径为什么通常不需要锁

get、containsKey 和迭代器不会取得 bin 锁；它们通过 volatile 读取表槽位、节点值和后继指针。读线程要么看到完整的旧 bin，要么看到 ForwardingNode 并跳到新表，不会读到“拆了一半”的链。

但“读无锁”不等于“读到精确快照”：迭代器是弱一致的，size() / isEmpty() 在并发修改时只能反映某个瞬间的近似状态，批量操作也不提供全局一致视图。

设计交换：CHM 用不可变式发布和弱一致契约，换取读路径不阻塞写路径。读无锁不是免费得到的，它把一致性要求交给了 API 契约。

7. 三个结论

1
锁的粒度由结构决定。JDK 8 锁的是发生结构变化的 bin，而不是整张表。
2
锁保护的是结构。空槽的一次 CAS 不需要锁，链表或树的改动才需要互斥。
3
无锁读对应弱一致性。CHM 不承诺遍历、计数和批量操作构成同一时刻的全局快照。
